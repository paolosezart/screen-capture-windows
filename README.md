# ScreenShotCli

Автономная консольная утилита для Windows x64: делает снимки прямоугольной области виртуального рабочего стола или активного окна и сохраняет их в PNG.

- Реализация: Go 1.23.
- Внешние Go-модули и .NET Runtime не требуются.
- Используются Win32 API (User32/GDI).
- Поддерживаются виртуальный рабочий стол и мониторы с отрицательными координатами.

> README описывает функции, уже присутствующие в исходниках и сборках. Новые возможности добавляются сюда вместе с реализацией и проверкой CI.

## Скачать

Все сборки и версии находятся на странице **[GitHub Releases](https://github.com/paolosezart/screen-capture-windows/releases)**.

- **Latest continuous build** — последняя автоматическая предварительная сборка из рабочей ветки. Подходит для проверки новых функций, может изменяться.
- **Версионные релизы** (vX.Y.Z) — отдельные зафиксированные выпуски с описанием изменений. Для обычного использования выбирай последний стабильный релиз.

Каждый опубликованный релиз содержит:

- ScreenShotCli-win-x64.zip — архив с автономным ScreenShotCli.exe.
- SHA256SUMS.txt — SHA-256 архива для проверки целостности.

### Проверка SHA-256 в Windows

Распакуй архив и проверь ZIP командой PowerShell:

~~~powershell
Get-FileHash .\ScreenShotCli-win-x64.zip -Algorithm SHA256
~~~

Сравни значение Hash с соответствующей строкой в SHA256SUMS.txt.

## Быстрый старт

Снимок области 800×600 пикселей от координат (0, 0):

~~~bat
ScreenShotCli.exe --x 0 --y 0 --width 800 --height 600 --output "C:\Screenshots\part.png"
~~~

Другой пример — область 1280×720:

~~~bat
ScreenShotCli.exe --x 100 --y 200 --width 1280 --height 720 -o "D:\Capture\screen.png"
~~~

Захватить активное окно с пятисекундной паузой, чтобы успеть переключиться на нужное приложение:

~~~bat
ScreenShotCli.exe --active-window --delay 5 -o "active-window.png"
~~~

Посмотреть встроенную справку и версию:

~~~bat
ScreenShotCli.exe --help
ScreenShotCli.exe --version
~~~

## Захват активного окна и задержка

Захватить активное окно целиком:

~~~bat
ScreenShotCli.exe --active-window --output "%USERPROFILE%\\Pictures\\active-[YYYY][MM][dd]_[HH][mm][ss].png"
~~~

Если программа запускается из BAT-файла или консоли, сначала активным может оказаться само окно консоли. Добавь задержку и за это время щёлкни по целевому приложению:

~~~bat
ScreenShotCli.exe --active-window --delay 5 --output "%USERPROFILE%\\Pictures\\window.png"
~~~

После задержки программа получает текущее foreground-окно. Если это классическое окно консоли, из которой запущена утилита, захват прекращается с понятной ошибкой вместо сохранения скриншота консоли.

Для получения изображения используется Win32 PrintWindow с флагом PW_RENDERFULLCONTENT. Если окно не поддерживает PrintWindow, применяется резервный экранный захват через BitBlt. В резервном режиме перекрытые другими окнами участки могут содержать изображение перекрывающего окна. Некоторые GPU-приложения, браузеры, защищённое содержимое и окна с аппаратным рендерингом могут возвращать чёрный или неполный кадр даже при успешном вызове PrintWindow.

Утилита не вызывает SetForegroundWindow, ShowWindow или другие функции активации/восстановления целевого окна. Поэтому отдельный переключатель --no-activate пока не нужен: неактивировать окно — штатное поведение режима.

## Параметры командной строки

| Параметр | По умолчанию | Назначение |
|---|---:|---|
| --x | 0 | X-координата левого верхнего угла области |
| --y | 0 | Y-координата левого верхнего угла области |
| --width | 800 | Ширина области в пикселях |
| --height | 600 | Высота области в пикселях |
| --output, -o | screenshot.png | Путь и имя выходного PNG |
| --overwrite | выключен | Разрешить перезапись файла с указанным именем |
| --sanitize-char | [!] | Замена недопустимых символов в динамических частях имени |
| --active-window | выключен | Захватить активное окно вместо области рабочего стола |
| --delay | 0 | Подождать указанное число секунд перед захватом (0–3600) |
| --version | — | Показать версию программы |
| --help, -h | — | Показать справку |

## Примеры

Сохранить снимок в текущую папку:

~~~bat
ScreenShotCli.exe --x 0 --y 0 --width 1920 --height 1080 -o "desktop.png"
~~~

Сохранить область второго монитора (координаты зависят от расположения экранов в настройках Windows):

~~~bat
ScreenShotCli.exe --x 1920 --y 0 --width 1920 --height 1080 -o "monitor-2.png"
~~~

Использовать переменную окружения и дату в имени:

~~~bat
ScreenShotCli.exe --x 0 --y 0 --width 800 --height 600 --output "%USERPROFILE%\Pictures\Screen-[YYYY]-[MM]-[dd]_[HH]-[mm]-[ss].png"
~~~

Не перезаписывать существующий файл (поведение по умолчанию):

~~~bat
ScreenShotCli.exe --x 0 --y 0 --width 800 --height 600 -o "shot.png"
~~~

Если shot.png уже существует, будет выбран следующий свободный путь: shot-conflict01.png, shot-conflict02.png и так далее.

Явно разрешить перезапись:

~~~bat
ScreenShotCli.exe --x 0 --y 0 --width 800 --height 600 -o "shot.png" --overwrite
~~~

## Шаблоны имени файла

В значении --output поддерживаются токены даты и времени:

| Токен | Значение |
|---|---|
| [YYYY] | Год, 4 цифры |
| [MM] | Месяц, 2 цифры |
| [dd] | День, 2 цифры |
| [HH] | Часы, 24-часовой формат |
| [mm] | Минуты |
| [ss] | Секунды |
| [MS] | Миллисекунды |
| [timestamp] | Unix timestamp |

Также поддерживаются переменные окружения в формате Windows: %TEMP%, %USERPROFILE% и другие существующие переменные. Неопределённая переменная считается ошибкой.

В коде шаблонов предусмотрены токены для заголовка окна и процесса: [window-title], [Windows title], [Windows tittle], [process]. Подстановка реальных данных окна будет включена вместе с функциями захвата окон; до этого не рассчитывай на них как на источник фактического заголовка.

Недопустимые для имени файла Windows символы и управляющие символы заменяются значением --sanitize-char. По умолчанию используется [!]. Зарезервированные имена Windows (например, CON, NUL, COM1) также обрабатываются.

## Правила сохранения

- PNG сохраняется по указанному пути, если папка существует и доступна для записи.
- Если исходный путь недоступен, программа пытается сохранить файл рядом с EXE; затем — в %LOCALAPPDATA%\ScreenShotCli.
- Отсутствующие папки в исходном пути автоматически не создаются.
- Без --overwrite существующие файлы не заменяются: добавляется суффикс -conflictNN.
- С --overwrite целевой файл открывается с усечением содержимого. Используй параметр осознанно.
- При резервном сохранении программа сообщает об исходном и фактическом пути.

## Ограничения захвата

- Область должна целиком находиться внутри виртуального рабочего стола Windows.
- Максимальная ширина или высота — 16384 пикселя.
- Максимальная площадь — 100 000 000 пикселей.
- Координаты виртуального рабочего стола могут быть отрицательными, если монитор расположен слева или выше основного.
- Захватывается изображение рабочего стола текущего интерактивного пользователя; курсор отдельно не добавляется.
- Защищённое содержимое, DRM и некоторые системные экраны могут не захватываться.
- Не запускай утилиту от имени администратора без необходимости.

## Сборка из исходников

Требуется Go 1.23 или новее. Для сборки Windows x64 из PowerShell:

~~~powershell
$env:GOOS = "windows"
$env:GOARCH = "amd64"
$env:CGO_ENABLED = "0"
go test ./...
go build -trimpath -ldflags="-s -w" -o ScreenShotCli.exe .
~~~

Используются стандартная библиотека Go и Win32 API. Cgo и сторонние Go-модули не требуются.

## CI/CD и версии

GitHub Actions выполняет тесты, собирает Windows x64 EXE, упаковывает ZIP и создаёт SHA-256.

- Изменения рабочей ветки публикуются в предварительный релиз continuous.
- Версионные релизы публикуются по тегам вида v0.3.0, v0.4.0.
- Для каждой новой возможности сначала обновляются исходники, тесты и этот README; затем проверяется CI и публикуется соответствующая сборка.
- Стабильный релиз должен содержать описание изменений и готовые файлы для скачивания.

Исходники и YAML-файлы проекта хранятся в UTF-8 без BOM, с окончаниями строк LF.
